# Отчёт о задании

**Задача.** По результатам OCR российских внутренних паспортов в формате JSONL необходимо для каждого документа принять решение: принять извлечённые данные (`accept`) либо запросить повторное сканирование (`reject`). Принятие считается правильным, только если **все 10 полей** совпадают с эталоном после нормализации регистра и повторяющихся пробелов, а паспорт действителен на **1 октября 2026 года**. Ошибочное принятие существенно дороже отказа, поэтому выбран консервативный подход.

**Итоговое решение.** Реализован трёхэтапный конвейер, работающий локально на CPU без сетевых запросов:

1. **Формальные проверки и согласованность OCR/MRZ:** наличие полей, уверенность распознавания полей и символов, форматы дат, номера паспорта и кода подразделения, контрольные суммы MRZ, согласованность MRZ с визуальной зоной по ФИО, номеру, полу, дате рождения, дате выдачи и коду подразделения.
2. **Текстовые эвристики:** отклонение подозрительно обрезанных или неполных значений места рождения и органа выдачи.
3. **Оценка риска ML:** две специализированные модели CatBoost для полей `Birth_place_ru` и `Issue_organization_ru`. При оценке риска ошибки **≥ 0,05** хотя бы одной моделью документ отклоняется. Признаки включают геометрию OCR, уверенность распознавания, количество строк и длину текста. Обе модели обучены на 3000 размеченных документах; при запуске на тесте эталоны не используются.

**Как выбирали подход.** Сначала проверялись правила и многоэтапная валидация, затем дополнительные классификаторы ошибок (включая ExtraTrees, CatBoost и текстовые признаки TF-IDF). Выбор сделан в пользу двух моделей на наиболее рискованных текстовых полях: они снижали количество ошибочных принятий при небольшом сокращении числа правильных. Подробная история экспериментов вынесена в отдельный документ.

**Экспериментальная оценка.** На пяти повторных, **пересекающихся** проверочных выборках по 600 документов многоэтапная система без ML принимала в среднем **203,2 правильных и 7,8 ошибочных** документа. С дополнительным ML-фильтром и фиксированным порогом 0,05 — **201,2 правильных и 3,0 ошибочных**. Результаты ориентировочные: правила и порог подбирались с учётом доступной обучающей выборки, а проверочные подвыборки пересекались. Следовательно, это не независимая оценка точности и не гарантия отсутствия ошибок. Скрипт `evaluate.py` сопоставляет текстовые поля, но отдельно не устанавливает юридическую действительность паспорта.

**Результат на тесте и прогноз.** На **2000** тестовых документах без эталонной разметки принято **690 (34,5%)**, отклонено **1310 (65,5%)**: на первом этапе — 1263, на втором — 8, на третьем — 39. Экстраполяция экспериментального соотношения 3,0 ошибочных принятия на 204,2 принятых документа даёт прогноз **около 10 ошибочных принятий среди 690**. Это приблизительная оценка с существенной неопределённостью; реальное число может отличаться из-за сдвига распределения, подбора порога и недоступных признаков действительности паспорта.

**Проверка действительности и ограничения.** Проверяются доступные по OCR условия: выдача не ранее 14-летнего возраста, дата выдачи не позднее 01.10.2026, необходимость замены при достижении 20 и 45 лет с учётом 90-дневного срока. Факт утраты, аннулирования, подделки и иные юридические основания недействительности невозможно установить только по предоставленным OCR-данным. Поэтому решение проверяет **вычислимые признаки действительности**, но не подтверждает официальный статус каждого паспорта.

**Воспроизведение.** После локальной установки зависимостей из `requirements.txt` запуск выполняется одной командой:

```bash
python postprocess.py data/test_predictions.jsonl answers.jsonl
```

На выходе — по одной JSON-записи с `doc_id` и решением для каждого входного документа; `fields` включаются только при `accept`. Обученные модели находятся в `models_v029/` и не требуют повторного обучения.
