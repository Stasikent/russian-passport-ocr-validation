# OCR passport postprocessing — technical report

**Task.** Given OCR JSONL for Russian domestic passports, decide whether to accept the complete ten-field extraction or request a rescan. A document is counted correct only if **all ten fields** match the reference (ignoring case and repeated whitespace) and the passport is valid as of **1 October 2026**.

**Method.** A conservative offline CPU pipeline performs three stages: (1) checks OCR field/character confidence, missing fields, dates, number and department-code formats, MRZ checksums and agreement of the MRZ with visible-zone name, number, sex, birth date, issue date and department code; (2) rejects suspicious truncated birthplace/issuing-authority phrases; (3) uses two CatBoost models, separately trained to predict errors in `Birth_place_ru` and `Issue_organization_ru`, and rejects if either model's predicted risk is ≥0.05. The classifiers use raw OCR geometry, confidence, and line/length statistics; training labels are never needed for inference. Both models were fitted using 3,000 labeled training documents. All dependencies and model files are bundled for offline execution.

**Experiments.** On five repeated, overlapping 600-document holdouts, the rule-only baseline accepted on average **203.2 correct and 7.8 incorrect** documents. The added field-level ML filter with fixed threshold 0.05 accepted **201.2 correct and 3.0 incorrect**. These experiments are exploratory: the rule set and threshold were developed after inspection of the overall labeled dataset, and the holdouts overlap. The comparison therefore cannot establish an unbiased test-set error rate or guarantee zero incorrect acceptances. The standalone `evaluate.py` only compares text fields; it does not test passport validity.

**Test prediction.** On 2,000 unlabeled test records, the final pipeline accepts **690** (34.5%) and rejects **1,310**: 1,263 at the initial stage, 8 at the text stage, and 39 at the ML stage. Extrapolating the exploratory mean of 3.0 incorrect among 204.2 accepted documents to 690 accepted test documents gives **approximately 10 incorrect acceptances**. This is an uncertain point forecast, not a guarantee; differences in test distribution, tuning bias and unverifiable passport validity may increase it. A reasonable qualitative statement is that a nonzero number of errors remains likely.

**Validity and limitations.** Date checks include issuance after the 14th birthday, issue date not later than 01.10.2026, and mandatory replacement around ages 20 and 45, with a 90-day grace period. These are only screenable conditions. Revoked, reported lost, fraudulent or otherwise invalid passports cannot be verified from OCR alone. We therefore cannot assert that every accepted document is legally valid. The requirement of zero wrong acceptances cannot be guaranteed with the supplied signals.

**Reproduction.** Install requirements locally, then run `python postprocess.py data/test_predictions.jsonl answers.jsonl`. The output contains one `doc_id`/decision JSON record per input document; `fields` are included only for accepted documents.
